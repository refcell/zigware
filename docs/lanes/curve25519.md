# Lane: curve25519

Owns `src/cryptography/curve25519` (package `curve25519`, the port of
`commonware-cryptography-curve25519`). The crypto lane owns `src/cryptography/ed25519`, which
this package wraps; changes there go through the crypto lane first.

Reference: `~/.cache/zigware/commonware-ref/cryptography/curve25519`.

## Public API (on main)
- `curve25519.signing`: `SigningKey` (`from_seed([32]u8)`, `random(rng)`, `deinit`,
  `verifying_key`, `sign(namespace, message)`, `sign_raw(message)`), `VerifyingKey`
  (`from_bytes([32]u8)` accepts any 32 bytes; `verify(namespace, message, *const Signature)`,
  `verify_raw`, `verify_batch(rng, items, projector, strategy)` over
  `cryptography.BatchEntry(VerifyingKey)`, `verify_batch_raw(rng, []const RawEntry,
  strategy)`, `eql`/`order` by encoding), `Signature` (`[64]u8`). All encode through codec
  and have `arbitrary`.
- `curve25519.key_exchange`: `SecretKey` (`random`, `from_raw`, `deinit`, `public_key`,
  `exchange(PublicKey) ?SharedSecret`, null when the shared secret is all zero), `PublicKey`
  (equality by u-coordinate mod p with bit 255 masked), `SharedSecret`.

## Semantics (must match commonware exactly)
- Ed25519 is ZIP-215: `A` and `R` decode leniently (non-canonical y, small order), `s` must be
  canonical, and the check is cofactored, `[8](sB - R - kA) = 0`. A batch's verdict equals
  every item's single verdict; an empty batch or one longer than `maxInt(u32)` is rejected.
- X25519 is RFC 7748 (bit 255 of `u` masked, non-canonical `u` reduced), and an all-zero
  shared secret is rejected.

## Decisions
- std.crypto stays where the vectors prove it agrees: `ed25519.core` (std Edwards25519 with a
  lenient decoder) for Ed25519 and `std.crypto.dh.X25519` for X25519. Field and group arithmetic
  stays std's. Single verification ports the crate's half-size Straus check
  (`verify_msm.zig`) and its AVX-512 IFMA point backend (`verify_ifma.zig`); the bucket MSM runs
  on IFMA, then curve25519-dalek's AVX2 backend (`verify_avx2.zig`), then std's arithmetic. The
  crate's portable and NEON backends are not ported (be8adb17, f822e640, ec084dae).
- Batches use the crate's own path (`batch.zig`), not `ed25519.core.verify_batch`, which stays
  as commonware's `cryptography::ed25519` batch (transcript noise coefficients). `z_i` is lane
  `i % 4` of SHA-512(seed || u64_le(i / 4)), so the verdict is a function of the items and the
  seed at every thread count. The crate builds one heap MSM per batch with a size-tuned window
  (`width_for`, 6 to 10 bits); zigware has no allocator in `verify_batch`, so each strategy
  batch is cut into chunks of at most 128 signatures (257 terms, about 42 KB of stack), whose
  sums add before the one cofactored check. 257 terms is below 2^10, where `width_for` always
  picks its minimum, so the width is fixed at 6 and `width_for` is not ported. Signer `A`
  points are normalized to Z = 1 per chunk with one batch inversion, for mixed addition.
- commonware fuzzes against ed25519-consensus and x25519-dalek. zigware has no third-party
  code, so `reference.zig` is an independent, naive implementation (u256 field mod p,
  extended-coordinate unified addition, double-and-add, the RFC 7748 ladder) that shares
  nothing with std.crypto. It passes the crate's vectors itself, and mutation checks (strict
  `y` decoding, unmasked X25519 `u`) make the fuzz tests fail.
- The conformance test skips in Debug without `-Dslow-tests` (65536 point decodings), as
  cryptography's does; CI runs ReleaseSafe.
- The package lives at `src/cryptography/curve25519` like the crate; `build.zig`'s `Package`
  gained an optional `dir`.
